## The instruments, and the traps in them

Three instruments produced wrong readings before they were checked. Every one of
those readings was reported as a finding first and withdrawn afterwards. **Validate
the instrument before drawing a conclusion from it.**

- **`scripts/blastem_events.py`** reads BlastEm's event log (`blastem -b N -e FILE`).
  `Event.cycle` is absolute time; `Reader.raw` is the 32-bit counter BlastEm holds,
  which wraps and which `EVENT_ADJUST` deducts from. `EVENT_FLUSH` is **not** a frame
  marker (it is an output-buffer flush whose count merely lands near the frame
  count); use `Reader.frame_of`. A cycle is **one master clock** *(corrected later
  on 2026-09-24: this line said half a master clock, which doubled every frame
  number)*, and **`-b N` runs N/2 frames**: ask for twice what you want.
  The reader consuming the body exactly is what says the decode is right.
- **A distinct-row count does not find a corrupted frame, and is inverted.** The four
  Overdrive 2 frames confirmed broken score 0.226-0.620 on periodicity while a
  *correct* grey cube on black scores 0.892: a mostly-black scene is hugely
  self-similar and a dense plaid has every row distinct. Pixel statistics do not
  separate these. Do not revive this; use a reference.
- **Comparing instantaneous VDP registers says nothing** for a game with raster
  effects. Earthion's registers 0, 10, 12 and 13 differ between the board and BlastEm
  after 600 frames purely by sampling phase. Compare streams, not snapshots.
- **Frame number is not a common clock.** The board and BlastEm are at different
  points in a game at the same frame count. Align on write-stream position.

## How to chase Overdrive 2

Everything below is done and checked; the diff is the next step.

- The demo is **PAL only** (`MACHINES["megadrive"]`), 12,000 frames = 240 s, and runs
  in about 420 s with `board.fm.enabled = False`.
- **BlastEm's reference log exists and reads correctly**: 20,545,852 events over
  **12,002 frames**, decoding to byte 76,821,806 of 76,821,806. *(Corrected later on
  2026-09-24: that log holds **6,001** frames and ends before frame 7,200, so it never
  contained a broken frame. `-b 24000` gives the whole demo: 65,160,157 events over
  12,001 frames, 211,063,218 bytes. See docs/worklog.md, "The BlastEm clock".)*
  Regenerate with
  `blastem -b 12000 -e FILE "Overdrive 2 ... .md"` from a directory holding *only*
  that image -- a `*.md` glob in a directory with two images picked the wrong one
  once already.
- **A VRAM replay of that log is faithful, and this was validated rather than
  assumed.** The risk was that BlastEm logs the register writes that trigger a DMA
  but not the bytes it moves. Earthion settles it: the board's **380,340 VRAM byte
  writes are identical to BlastEm's, address and value, in order**, with no address
  transform. So replaying the log's VRAM events reconstructs VRAM faithfully, and
  `_vram_write_byte`'s address is the convention the log uses.
- The diff to build: rebuild BlastEm's VRAM/CRAM/VSRAM at a chosen point, compare
  against the board's, and walk back from frame 7,200 to the first point where the
  **data** diverges -- not the picture. No heuristic anywhere in that chain.
- **Align on write-stream position, not frame number** (item 21), and show the
  alignment holds before diffing anything.

## Things that are settled, so they are not re-litigated

- **`$A130F0` on Extended SSF carts is the Sega mapper's SRAM control**, as MAME has
  it and against krikzz's own document, because the games were observed
  ([undocumented-behavior.md](undocumented-behavior.md) item 20). krikzz's document
  describes his Everdrive flashcart; a pressed cartridge is not that.
- **The board's DMA rate is the Manual's**, ratio 1.00 (item 21).
- **BlastEm is a detector**, never a judge, however good it is. The tier rule is not
  negotiable ([validation.md](validation.md)).
- **Its framebuffer backend does not build** at the pinned revision and was
  deliberately not patched: a patched oracle stops being an independent one. Its
  debugger is unusable headless (it spawns a terminal emulator). The event log is
  the way in.

## Working agreement, the parts easiest to forget

- Commits use `git -c user.name=alewman -c user.email=alewman@gmail.com`.
- Never commit ROMs, BIOS images, saves, traces, recordings, fetched material or
  referee builds. `reference/` and `tests/compat/` are gitignored; keep it that way.
- Never copy GPL/AGPL/LGPL/non-commercial code. Read it, cite it by file and line,
  write our own.
- `/data/emu/source` is master and regeneration is deterministic: never hand-fix a
  generated romset. That is rom-farmer's job, a different project.
- Shared machine: `nice`, at most 16 parallel processes, delete large intermediates.
  Never use `until ! pgrep -f X` wait loops -- they match their own shell and hang.
- Verify before pushing, on **both** interpreters. Piping `pytest` through `tail`
  means no output appears until the pipeline exits, so an empty output file is not a
  signal.
